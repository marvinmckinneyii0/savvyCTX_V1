# Humanize Writing

SavvyCTX includes a reusable post-processing layer for AI-generated prose. It is designed for emails, LinkedIn posts, marketing copy, business reports, and general agent output where the meaning is correct but the wording sounds overly generated.

The design is adapted from [lguz/humanize-writing-skill](https://github.com/lguz/humanize-writing-skill), which uses a three-pass editing model: remove high-signal AI vocabulary, break formulaic AI sentence structures, then apply a more natural voice. The upstream project is MIT licensed; see `THIRD_PARTY_NOTICES.md`.

## API

`POST /api/humanize`

Example request:

```json
{
  "text": "Furthermore, this pivotal initiative will leverage a robust framework to enhance operational efficiency.",
  "voice": "warm-professional",
  "contentType": "email",
  "preferLlm": true
}
```

Example response shape:

```json
{
  "text": "This initiative will use a strong framework to improve operational efficiency.",
  "mode": "llm",
  "before": {
    "score": 42,
    "risk": "medium",
    "wordCount": 12,
    "findings": []
  },
  "after": {
    "score": 0,
    "risk": "low",
    "wordCount": 10,
    "findings": []
  }
}
```

The score is a heuristic for obvious AI-writing patterns. It is not an AI-detector probability and should not be presented as proof that text was or was not generated by an LLM.

## Voices

- `clear-thinker` — direct, intelligent, low-decoration prose.
- `casual-storyteller` — conversational and loose without inventing anecdotes.
- `sharp-opinionated` — concise, direct, low-hedging prose.
- `warm-professional` — client-safe business writing that avoids corporate filler.
- `mirror` — matches a supplied writing sample. `writingSamples` is required for this mode.

## Content types

- `general`
- `linkedin`
- `email`
- `marketing`
- `report`

Content-type rules protect context. For example, report mode keeps technical labels and metrics intact, while LinkedIn mode favors shorter sentences and avoids generic “thought leadership” phrasing.

## LLM configuration

The server can call any OpenAI-compatible chat-completions endpoint. This works well behind LiteLLM and keeps the feature independent of a specific model vendor.

Set:

```bash
HUMANIZE_LLM_MODEL=your-model-name
HUMANIZE_LLM_BASE_URL=https://your-openai-compatible-endpoint/v1
HUMANIZE_LLM_API_KEY=your-api-key
```

`HUMANIZE_LLM_BASE_URL` defaults to `https://api.openai.com/v1` when omitted. When using that default, an API key is required.

If no LLM is configured, SavvyCTX automatically uses a conservative local cleanup pass. The local pass removes high-signal vocabulary, stiff transitions, dramatic setup phrases, and excessive em dashes. It intentionally does not perform aggressive structural rewrites because those are more likely to change meaning without an LLM.

## Integration from another route or agent

```ts
import { humanizeText } from '@/lib/humanize';

const result = await humanizeText({
  text: generatedDraft,
  voice: 'warm-professional',
  contentType: 'email',
});

return result.text;
```

For user-specific content, use `mirror` and pass a real writing sample:

```ts
const result = await humanizeText({
  text: generatedPost,
  voice: 'mirror',
  contentType: 'linkedin',
  writingSamples: userWritingSample,
});
```

## Guardrails

The rewrite prompt instructs the model to preserve names, dates, numbers, measurements, commitments, product names, technical terms, and factual claims. Source text is treated as untrusted content so embedded instructions are not followed.

The humanizer should be applied to prose, not code, API references, commit messages, structured data, or other content where exact wording is part of the technical contract.
